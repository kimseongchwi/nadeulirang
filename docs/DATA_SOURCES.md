# 원천 데이터 검토

상태: P06 공개 표본·문서 검토 완료, 인증키 미준비로 후속 검증 보류 · 확인일: 2026-10-02 (Asia/Seoul)

원천별 제공 항목·표본·이용 조건과 수집 전 확인할 내용을 관리한다. 제품 기준은 [PRD](PRD.md), 완료 상태는 [PLAN의 P06](../PLAN.md#요구사항과-디자인)을 따른다. 원천 검토 근거는 수집·운영 판단에 필요하므로 이 문서에 보존하고, 일일 수행 결과는 로컬 WORKLOG에 기록한다.

## 검토 범위

공공데이터포털의 공개 그리드와 API 설명을 열람했다. 전체 파일 다운로드·인증 API 호출·자동 수집·현장 운영 확인은 수행하지 않았다. 아래 표본은 수집 후보의 품질 확인용이며 현재 방문 가능·실제 결제 금액을 보증하지 않는다. 데이터기준일자·포털 수정일·이번 열람일은 서로 다른 시각이다.

트래픽 수치는 포털에 게시된 신청 가능 값이다. 표준데이터 API의 한도 시간 단위·초당 제한과 승인 계정에 실제 적용되는 값은 인증 후 확인한다. 한도 초과를 유도하는 부하 검증은 하지 않는다.

## 공개 표본 관찰

축제 2행·시설 5행으로 6개 사례를 검토했다. 의도적으로 일정·요금 누락과 조건부 요금·중복 사례를 골랐다. 무작위 표본이나 전체 데이터의 누락률로 해석하지 않는다. 아래 이름·기준일로 각 원천 페이지에서 행을 다시 찾을 수 있으나, 이름을 영구 식별자로 사용하지 않는다.

## PRD 필수 정보와의 차이

다음은 표본과 공개 명세를 근거로 한 구현 검토 사항이며, 원천 채택·공개 지역·종류의 최종 결정은 보류한다.

| 필요한 정보 | 확인 결과 | P11 전 확인·처리 |
|---|---|---|
| 원본 식별자 | 표준데이터 명세에 안정된 개별 행 ID가 보이지 않음. | TourAPI 식별자 확인. 보완 원천에는 기관·주소·이름 등을 이용한 연결 후보와 수동 검토 기준을 정한다. 페이지·행 순번으로 식별하지 않는다. |
| 이름·종류·시도 | 이름·주소는 확보 가능. 시설 구분 표본의 공립·사립 등은 설립 형태이며 제품의 박물관·전시 구분과 다름. | 원천 코드와 제품 종류 매핑을 검증한다. 주소의 시도 정규화 실패는 추정하지 않고 검토 대상으로 둔다. |
| 출처·확인 시각 | 데이터셋 URL·일부 공식 홈페이지·행 기준일 존재. 일부 홈페이지는 누락되거나 스킴이 없음. | 데이터셋·항목별 공식 출처를 구분하고 실제 수집 시각·마지막 성공 확인 시각을 별도 기록한다. 공식 예약 링크도 따로 확인하며 없으면 미확인으로 표시한다. |
| 방문 날짜 | 기간 또는 운영시간·휴관 문장은 확보 가능. | 공휴일·대체 휴관·임시 휴관 근거와 오래된 정보 처리 기준을 확정한다. 해석되지 않은 문장은 원문을 유지하고 날짜 검색에서 운영 확인으로 취급하지 않는다. |
| 요금·할인·예약 | 축제 요금 미확인, 시설에는 숫자와 조건 문장이 혼재. | 일반 요금·조건부 무료·추가 요금을 분리하고 누락을 0원으로 채우지 않는다. 대상·기간·증빙·중복 적용 확인 전 자동 계산·할인 적용을 하지 않는다. |
| 변경·취소·삭제 | 공개 표준 필드만으로 취소·삭제를 판정할 수 없음. | 원천 동기화 상태·공식 공지 확인. 응답 실패·목록에서 일시 누락을 취소·삭제로 바꾸지 않는다. |

축제·시설 보완 자료만으로 행사·전시·문화관광지 전체 범위의 적합성을 확인한 것은 아니다. P05의 다섯 종류와 실제 원천 분류를 대조하고, 대표 시나리오가 성립하는 지원 범위를 P06 완료 시 판단한다.

## 이용 조건

- TourAPI 포털 메타데이터는 이용허락 제한 없음으로 안내하지만 사진에는 공공누리 1·3유형과 별도 사용 제한이 있다. API별 이미지의 유형·출처·변경 허용을 확인한 뒤 채택한다. [제공기관 안내](https://www.data.go.kr/data/15101578/openapi.do)
- 공공누리 1·3유형은 출처 표시와 상업 이용이 가능하며, 3유형은 변경 제한이 있다. 포털의 일반 안내는 개별 파일·이미지의 이용허락을 대신하지 않는다. 표준데이터의 기관별 이용허락·사진 권리는 이번에 확정하지 못했다. [공공데이터 이용정책](https://www.data.go.kr/ugs/selectPortalPolicyView.do)
- 콘텐츠랩의 OpenAPI 가이드는 기획·디버깅 참고용으로 안내하며 무단 캐싱·크롤링을 금한다. 실제 저장용 데이터는 활용신청한 API 등 허용된 경로로 확보한다. [콘텐츠랩 FAQ](https://api.visitkorea.or.kr/?loginFlag=sso)
- 공개 표준 명세의 한도 초과·인증·연결 실패 코드와 TourAPI 포털의 일일·초당 제한 오류 설명은 읽었지만 실제 오류 응답 형식은 미검증이다. HTTP 성공 여부와 원천 결과 코드를 함께 검사하도록 P11에서 설계한다.

## 인증키 준비 후 이어갈 검증

1. [TourAPI 활용신청 페이지](https://www.data.go.kr/data/15101578/openapi.do)에서 개발계정 승인·현재 활용 매뉴얼·계정 호출 한도를 확인한다. 로컬 설정 이름은 `TOURAPI_SERVICE_KEY`이며 빈 예시는 [루트 .env.example](../.env.example)에 둔다. 키는 Git·채팅·요청 URL 로그에 남기지 않는다. 현재 실행 코드에는 환경 파일을 자동으로 읽는 기능이 없다.
2. 승인된 오퍼레이션으로 행사·전시·박물관·문화관광지 대표 표본의 목록·상세를 조회해 식별자·지역·종류·일정·요금·할인·공식 링크·상태·수정 시각을 대조한다. 요금 무료·유료·미확인과 조건부 무료·추가 요금 사례를 포함한다.
3. JSON/XML 형태·빈 값·0원·결과 없음·오류 코드와 목록/상세 일치, 같은 항목 반복 조회의 식별자 안정성을 확인한다. 인증 성공·요청 횟수·민감값을 제거한 관찰 결과만 기록한다.
4. 공개 가능한 지원 범위·원천별 이용허락·이미지 정책·갱신 예산과 주기·중복 및 취소 판정 근거를 확정한다. 대표 시나리오를 충족하지 못하면 P05에 범위 재검토 결과를 반영한다.

P06은 위 인증·이용 조건·지원 범위 검증 전까지 미완료로 유지한다. P07 시안은 공개 표본의 이름·일정·주소·일부 요금과 별도 표시한 예시 데이터를 활용해 먼저 검토할 수 있다. 표본 요금·일정을 현재 운영 정보로 확정하지 않으며 누락·미확인·조건부 요금 상태를 함께 다룬다. P11 수집 구현 전에는 원천 검증을 마치고 P07 화면에 반영할 데이터 제약도 다시 검토한다.
