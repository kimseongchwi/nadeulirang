# 원천 데이터 검토

상태: P06 표본 검증 완료·P11 수집 기준 확정 · 원천 확인일: 2026-10-03 (Asia/Seoul) · 문서 정리일: 2026-10-05

원천별 제공 항목·표본·이용 조건과 수집 전 확인할 내용을 관리한다. 제품 기준은 [PRD](PRD.md), 완료 상태는 [PLAN의 P06](../PLAN.md#요구사항과-디자인)을 따른다. 원천 검토 근거는 수집·운영 판단에 필요하므로 이 문서에 보존하고, 일일 수행 결과는 로컬 WORKLOG에 기록한다.

P11의 수동 소량 수집·저장 구현은 완료됐으며 자동 갱신·운영 검증의 상태는 PLAN을 따른다. P28에서 첫 공개에 제외한 방문일·요금 필터·비교는 이 문서에서도 P32 후속 참고 기준으로 구분한다. 문서 정리일을 원천 재조회·현장 운영 확인일로 해석하지 않는다.

## 검토 범위

P06 검토에서는 2026-10-02 공개 그리드와 API 설명을 열람했고, 2026-10-03 세 원천의 인증·소량 조회, 승인 계정의 상세 화면, 공식 활용 매뉴얼과 기관 관람 안내를 대조했다. 이 검토에서 전체 관광 데이터 파일 다운로드·자동 수집·현장 운영 확인은 수행하지 않았다. 표본 검증은 모든 시설의 현재 운영을 확인한 결과가 아니다. 데이터기준일자·포털 수정일·열람일은 서로 다른 시각이다.

## PRD 필수 정보와의 차이

다음은 초기 표본의 차이와 구현 항목이다. 후속 검증에 따른 원천 채택·종류 매핑·공개 포함 기준은 아래 P11 수집 기준을 따른다.

| 필요한 정보 | 확인 결과 | P11 구현 기준 |
|---|---|---|

## 이용 조건

- TourAPI 포털 메타데이터는 이용허락 제한 없음으로 안내하지만 사진에는 공공누리 1·3유형과 별도 사용 제한이 있다. API별 이미지의 유형·출처·변경 허용을 확인한 뒤 채택한다. [제공기관 안내](https://www.data.go.kr/data/15101578/openapi.do)
- 두 표준데이터의 승인 계정 라이선스 화면에서 공공누리 제1유형을 확인했다. 데이터셋·제공기관·행 기준일·조회 시각과 링크를 DB/API에 보존한다. 화면의 반복 표시를 줄이고 데이터셋·제공기관·원본 링크·이용 조건은 공통 푸터의 출처 안내에 모은다. [제1유형 안내](https://www.kogl.or.kr/info/license.do)는 출처 표시를 조건으로 상업 이용을 허용한다. 외부 홈페이지의 사진·전시 작품까지 같은 허락으로 처리하지 않는다.
- TourAPI 대표 사진은 마지막 성공 `detailCommon2` 응답의 `firstimage`·`firstimage2`·`cpyrhtDivCd`를 함께 대조한다. Type1과 한국관광공사 제공처·원본 근거가 확보된 사진만 연결하고 제공처/원천 링크·제1유형을 공통 안내에 표시한다. 제공기관을 사진 촬영자로 추정하지 않으며 별도 저작자 표기가 있는 자료는 해당 귀속 정보를 확보한 뒤 도입한다. Type3은 출처 표시와 변경금지 조건이 있으므로 첫 구현에서는 제외한다. 유형 공란·Type2·Type4·알 수 없는 유형도 제외한다. 출처가 없으면 텍스트만 제공한다. 원천 호스트의 확인한 JPG/PNG 주소만 HTTPS로 사용하고 바이너리 복제·크롭·필터·문자 합성·AI 편집을 적용하지 않는다. [제1유형 안내](https://www.kogl.or.kr/info/license.do)·[제3유형 안내](https://www.kogl.or.kr/info/licenseType3.do)
- 현재 별도 사용 중인 클레이아크 김해미술관 표본 사진은 [HappyMidnight의 2015년 Wikimedia Commons 자료](https://commons.wikimedia.org/wiki/File:Clayarch_Gimhae_Museum.JPG)다. [CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/)의 작성자·라이선스 링크·변경 표시 조건에 따라 원본 링크와 화면 크롭 정보를 보존한다. 공통 제공처 문장만으로 사진별 이용 조건을 대체하지 않는다.
- 콘텐츠랩의 OpenAPI 가이드는 기획·디버깅 참고용으로 안내하며 무단 캐싱·크롤링을 금한다. 실제 저장용 데이터는 활용신청한 API 등 허용된 경로로 확보한다. [콘텐츠랩 FAQ](https://api.visitkorea.or.kr/?loginFlag=sso)
- 공개 표준 명세의 한도 초과·인증·연결 실패 코드와 TourAPI 포털의 일일·초당 제한 오류 설명은 읽었지만 실제 오류 응답 형식은 미검증이다. HTTP 성공 여부와 원천 결과 코드를 함께 검사하도록 P11에서 설계한다.

## 2026-10-03 TourAPI 인증·표본 검증

사용자가 국문 관광정보 서비스 개발계정을 활용신청하고 로컬 `.env`에 키를 설정했다. 공식 명세의 기본 주소 `https://apis.data.go.kr/B551011/KorService2/`로 인증해 HTTP 200·원천 결과 코드 `0000`을 확인했다. 키·요청 URL·원본 오류를 출력하지 않는 [검증 도구](../scripts/verify-tourapi.mjs)를 만들었고 실행 방법은 [README](../README.md#원천-api-표본-검증)에서 관리한다. 계정의 실제 일일 한도·사용 기한은 공개 명세와 별도로 승인 계정 화면을 확인해 아래 계정 표에 기록했다.

- 법정동·분류체계·지역 목록·키워드·행사 목록·공통·소개·반복·이미지·동기화의 10개 오퍼레이션을 소량 조회했다. 성공 JSON, 성공 XML의 결과 코드·건수, 결과 0건, 반복 키워드 조회의 같은 식별자, 일반 응답과 다른 최상위 JSON 매개변수 오류 코드 `10`을 확인했다. 잘못된 이미지 매개변수를 제거한 뒤 정상 조회했고 도구에서 해당 매개변수를 차단한다. 인증 실패·한도 초과의 실제 응답은 유도하지 않았다.
- 검증 당시 10월 행사 조회 조건의 총건수는 257이며 상세 대조는 아래 6개 항목에 한정했다. 기간 검색 결과에 9월 시작·10월 종료 행사도 포함됐다. 이는 운영 요일·임시 휴관·취소까지 확인했다는 뜻이 아니다.
- 새 `lDongRegnCd`·`lDongSignguCd`와 `lclsSystm1`~`3`이 존재하고, 기존 `areacode`·`cat1`~`3`은 빈 표본이 있었다. 법정동 시도 목록은 16건이며 서비스 응답에 기존과 다른 지역 명칭·코드도 있어 최신 공식 코드와 대조 후 공개 지역 매핑을 정한다. 기존 코드만으로 지역·종류를 필터링하지 않는다.
- `contenttypeid`는 관광지 12·문화시설 14·축제공연행사 15를 확인했다. 새 분류의 문화관광·역사관광·축제/공연/행사와 제품의 다섯 종류는 일대일 대응하지 않는다. 전시관 검색 성공을 기간 전시 데이터 확보로 간주하지 않는다.

초당 허용량과 일일 집계 초기화 시각은 숫자로 안내되지 않았다. 개발 수집은 서버에서 직렬 요청하고 원천별 요청 시작 간격을 최소 1초로 둔다. 이는 제공기관이 보장한 초당 한도가 아니라 자체 제한이다. 초기 개발 수집은 최대 100개 후보와 코드·목록 호출 100회 이내로 제한한다. 후보당 공통·소개·반복 3회라면 전체 400회다. P38 로컬 배치도 요청당 20건·실행당 전체 400회 상한을 적용하고 이미 차감된 24시간 예산 안에서만 호출한다. 개발 도구의 표본 상한 20건은 유지하며 이미지 수집은 추가하지 않는다. 전국 전량 상세 수집·서비스 방문자별 원천 호출은 이 예산에 맞지 않는다. 운영계정 신청·운영 한도와 실제 예약 작업은 P15에서 확인한다.

## P11 수집 기준

TourAPI를 기본 원천, 두 표준데이터를 보완 원천으로 채택한다. P06은 다섯 종류의 확보 가능성과 누락·충돌·이용 조건을 확인하는 표본 검증으로 완료한다. 실제 수집·공개 건수와 사용자의 방문 가능 판단은 P11·P13에서 검증하며, 표본 수를 공개 데이터 확보 수로 표시하지 않는다.

### 전국 목록의 제한 배치 — P38

2026-10-05 로컬 키의 실제 응답으로 다음 목록을 확인했다. TourAPI 행사는 `searchFestival2`의 시작일 조회 구간을 실행 월 기준 1년 전~3개월 뒤 전날로 정하고, 응답의 종료일이 지난 행은 건너뛴다. 전체 장기 행사 확보를 뜻하지 않는다. 시설은 `areaBasedList2`의 박물관 코드 `14/VE/VE07/VE070100`과 역사 문화관광지 코드 `12/HS`를 사용한다. 세부 종류는 공통 상세의 최신 분류로 다시 판정한다.

두 표준 원천의 전국 목록에서 `numOfRows=20`과 `pageNo`를 확인했고 당시 `totalCount`는 박물관·미술관 1,076행, 축제 1,321행이었다. 전체 목록 크기이며 실제 수집·공개 건수가 아니다. 표준 JSON은 직접 `header`·`body`, TourAPI는 `response.header`·`response.body`로 내려오는 실제 차이를 보존하며 목록 끝 판정에 두 구조를 모두 사용한다.

신규 TourAPI 공개 후보는 이름·종류 분류·`ldongCode2`의 시도 코드/이름·주소 시작 부분과 기존 데이터 이용허락을 대조했다. 재조회에서 기존 승인 이름·종류·시도와 다르면 다시 검토 대기로 둔다. 새 표준 행의 교차 원천 연결과 지역 판정은 별도 검토 대상으로 유지한다. 조회 성공만으로 당일 운영·요금·예약을 확정하지 않는다. 현재 저장·노출 결과는 PLAN, 실행과 재개 방법은 [README](../README.md#데이터-수집-p11p38), 로컬 원문·검토 목록·검증 자료 경로는 `docs/WORKLOG.md`에서 관리한다.

### 식별자·중복·원천 충돌

- 내부 ID는 원천 업데이트와 별개로 유지한다. TourAPI 원본 키는 원천명+`contentid`다. 매뉴얼의 이전 ID 조회 기능은 이관 후보 확인에만 사용하며 이름이 같다는 이유로 ID를 바꾸지 않는다.
- 표준 시설은 기관·정규화한 이름·주소로 연결 후보를 만든다. 괄호/공백 차이를 정리하되 건물 번호는 보존한다. 식별이 같아도 상충 필드가 있으면 자동 통합하지 않는다. 표준 축제는 개최 회차/연도·기간·장소를 함께 검토해 전년도 행사와 분리한다. 행 순번·페이지는 키로 쓰지 않으며 원본 행 해시와 내부 연결 이력을 보존한다.
- 필드마다 값·원천·원천 기준일/수정 시각·조회 성공 시각·검토 시각·적용 기간을 저장한다. 검토된 기관 공식 공지의 해당 기간/시설 조건을 우선하되 다른 API 값과 원문을 지우지 않는다. API 간 충돌은 자동 최신 승자를 만들지 않고 검토 상태로 둔다. 충돌이 해결되기 전 요금·운영 조건은 미확인이다.
- 요금은 일반 성인·연령/자격별·조건부 무료·체험/주차 등을 분리한다. 빈 값은 미확인, 숫자 0은 해당 대상/항목의 무료다. 할인 대상·증빙·기간·중복 여부가 없으면 자동 적용하지 않는다. 일반 검색 요금은 할인 없는 일반 성인 입장 기준을 따른다.

### 갱신·오래된 정보·상태

아래 주기와 경계는 제공기관의 최신성 보증이 아니라 첫 구현의 정책이다. 예약 작업 자체는 이번에 만들지 않았다.

- 진행 중/90일 이내 시작 기간 행사: 원천 목록·변경 목록 매일 확인, 관련 상세는 변경 시 및 마지막 상세 성공 7일 경과 시 재확인. 조회 성공 48시간 초과는 갱신 지연으로 표시한다. 시작·종료 경계는 Asia/Seoul 달력 날짜로 판단한다.
- 상설 시설: 원천 변경 목록 매일 확인, 관련 상세는 변경 시 또는 30일마다 재확인. 마지막 성공 30일 초과는 오래된 정보로 표시한다. 할인·한시 무료·임시 휴관은 적용 기간과 별도 검토 기한을 둔다.
- 표준 원천: 월초 병합 후 월 1회 조회한다. 응답 기준일이 최근이라고 일정·요금이 바뀐 것으로 간주하지 않는다. 같은 행 해시 반복도 재수집 성공 시각만 갱신한다.
- `showflag=0`은 비표출로 검색 제외. 종료일이 지난 기간 행사는 종료, 공식 취소 공지가 확인되면 취소다. 목록 누락·0건·연결 실패만으로 취소·삭제·폐업을 추정하지 않는다. 마지막 정상 데이터는 보존하고 실패 이유·마지막 성공 시각을 표시한다.

### 방문일·요금 필터·비교 — P32 후속 참고 기준

첫 공개에서 활성화하지 않는다. 아래는 과거 검토의 데이터 요구 조건을 보존한 것이며 도입 여부·검증 범위는 P32에서 다시 정한다.

- 방문일 검색을 재개하면 최신 조회뿐 아니라 기간·요일·휴관·공휴일 예외·예약 시 운영을 공식 안내와 대조해야 한다. 진행 기간 행사의 조회 성공이 48시간을 초과하거나 날짜별 운영을 확인하지 못한 경우 방문 가능으로 포함하지 않는다. 새 API 응답만으로 오래된 운영 사실의 확인 시각을 올리지 않는다.
- 요금 필터를 재개하면 기준 요금과 적용 대상을 확인해야 한다. 요금 누락·조건부 무료를 일반 무료로 포함하지 않는다.
- 비교를 재개하더라도 운영·요금 미확인은 유지한다. 데이터 확보만으로 비교·계산 기능을 자동 복원하지 않는다.

### 공개 포함 기준과 후속 검증

이름·내부/원본 식별자·검토된 종류·지역·출처·수집/확인 시각을 확보하고 이용허락을 확인한 항목만 공개 후보로 둔다. 일정·운영·요금 누락은 표시하며 확인된 운영·무료로 추정하지 않는다. 원천 코드가 있다는 이유로 전국 모든 지역을 지원한다고 표시하지 않는다. 지역·종류 선택지는 실제 저장 후 검토를 통과한 후보에서 생성한다. P11의 표본 건수와 별개로 P12·P13에서 조회 시점의 노출 지역·종류·건수를 확인하며 현재 범위는 PRD의 P28 확정을 따른다.

P11의 중복·회차·충돌 요금·누락/0원·응답 실패/정상 0건·상태·연결 처리의 실제 검증 결과는 PLAN에서 관리한다. P12·P13은 공개 포함·시작/종료 경계·미확인·갱신 실패와 URL/화면 흐름을 실제 데이터로 확인한다. 방문일 운영 필터의 요일/공휴일 예외 판단은 P32 후속 기준이다. P15에서는 운영계정·한도·사용 기간·채택 이미지의 개별 출처를 다시 확인한다. 초당 수치·취소/삭제 실사례·기관별 당일 예산과 예약 잔여석은 표본 검증으로 확인한 값이 아니며 미확인 상태와 공개 제외 기준을 적용한다.
