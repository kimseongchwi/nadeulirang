# 제품 요구사항 (PRD)

상태: P28 첫 공개 범위 확정 · 최초 범위 확정일: 2026-10-02 · 재확정일·갱신일: 2026-10-05

제품 기준은 홈·이름/지역/종류 검색·상세·공식 출처·정책·검색 유입이다(P28). 날짜/요금 필터·비교/계산과 북마크/로그인/AI는 후속이다. 작업 상태는 [PLAN](../PLAN.md), 적용/미정 화면 기준은 [DESIGN](../DESIGN.md)을 따른다. 범위 확정과 기능 구현·공개 운영은 구분한다.

## 서비스 목표

전국 축제·행사·전시·박물관·문화관광지를 발견하고, 관심 있는 곳의 일정·방문 정보를 상세와 공식 출처로 확인한다. 개인 운영·검색 유입·광고 수익 목표는 유지한다. 현재 비교 기능은 첫 공개에서 제외한다.

## 대상 사용자와 방문 시나리오

주 대상은 국내 당일 나들이를 준비하는 성인이다. 혼자·동반자·아이와 방문할 곳을 찾으며, 방문 가능한 날짜와 일반 입장료·추가 요금·할인 조건을 공식 출처로 확인하려는 사용자를 우선한다. 숙박·교통 경로·여행 일정표 구성은 첫 공개 범위에 포함하지 않는다.

| 시나리오 | 사용자의 목표 | 완료 판단 |
|---|---|---|
| 주말 후보 찾기 | 이름·지역·종류로 축제·행사 또는 시설을 찾는다. | 조건에 맞는 후보와 일정의 확인 여부를 볼 수 있고 검색 URL을 다시 열어 같은 조건을 복원한다. |
| 동반 방문 조건 확인 | 박물관·전시의 일반 입장료, 아이 관련 할인과 별도 체험료·예약 조건을 확인한다. | 확보한 일반 요금과 추가 요금이 구분되고, 누락된 요금·할인·증빙·예약 조건은 확인 필요로 표시되며 공식 링크로 이동할 수 있다. |
| 나들이 발견 | 홈에서 진행 기간·다가오는 행사·상설 시설을 둘러본다. | 실제 확보한 항목의 기간·미확인 상태를 읽고 검색·상세로 이동할 수 있다. |

## 첫 공개 범위

대상 종류는 축제·행사·전시·박물관·문화관광지다. 서비스의 장기 목표는 전국 검색이며 첫 공개에서 실제 노출하는 지역·종류·건수는 P06에서 검증한 원천으로 P11에서 저장·검토한 데이터에 맞춘다. 확보하지 못한 지역을 지원 지역으로 표시하지 않는다.

P06에서 다섯 종류의 원천 매핑과 공개 포함 기준을 확인했다. 전시는 시설과 구별되는 기간 전시이며, 박물관 분류에는 기관 소개로 확인한 미술관도 포함하고 상세에 실제 시설 종류를 표시한다. 종류·지역의 선택지는 P11에서 실제 저장하고 검토한 항목에 맞춘다. 원천 채택·매핑·충돌·갱신 및 이용허락의 구현 기준은 [원천 검토](DATA_SOURCES.md#p11-수집-기준)에서 관리한다.

2026-10-03 사용자는 웹을 먼저 완성한 뒤 같은 모바일 화면을 웹뷰 앱으로 제공하는 순서를 선택했다. 첫 웹 공개는 모바일 중심 공통 서비스 화면을 사용하며 PC에서는 왼쪽 고정 안내와 오른쪽 서비스 화면을 제공하며 오른쪽 서비스 본문만 스크롤한다. 메뉴·필터·정책 모달과 어두운 배경은 오른쪽 서비스 영역 안에서 표시한다. 모바일에서는 서비스 화면이 화면 너비에 맞게 표시된다. 홈·기본 검색·상세와 필수 이용 정보는 모바일 화면에서도 모두 접근할 수 있어야 한다. PC 안내 영역의 세부 내용·화면 폭·전환 기준은 DESIGN의 후속 검토에서 정한다.

| 기능 | 기대 동작 |
|---|---|
| 홈 | 기본 전체 지역에서 진행 중·다가오는 기간 행사와 상설 시설을 둘러보고 검색·상세로 이동. 확보한 항목·날짜 근거와 빈 결과를 구분 |
| 검색·목록 | 이름 키워드·시도·종류·검색 범위로 검색. 홈 조건을 이어받고 검색에서 범위를 변경하며 조건과 페이지를 URL에 유지. 방문일 선택·요금 필터는 첫 공개에서 제외 |
| 상세 | 확보한 행사 일정 또는 시설 운영 정보, 주소·일반 요금·추가 요금·할인·예약 조건 제공. 출처·이용 조건은 공통 푸터 안내에 모으며 누락·갱신 필요는 상세에 표시 |
| 검색 유입 | 실제 자료와 맞는 자연스러운 제목·설명·본문과 발견 가능한 상세 링크 제공. 공개 대상별 검색 노출·대표 주소·sitemap의 일치와 필요한 수정은 P14에서 검증 |
| 정책·출처 안내 | 모바일·PC 공통으로 개인정보처리방침·이용약관·서비스/데이터 출처와 저작권 안내에 접근. 실제 운영 구성에 맞는 내용과 직접 접속 주소를 P15에서 검증 |

요금은 공지된 단가와 조건을 표시한다. 인원·연령 입력, 할인 자격 자동 판정, 예상 합계 계산은 첫 공개에서 제외한다. 확인하지 못한 요금 조건으로 합계를 계산하지 않는다.

로그인·결제·직접 예약·리뷰·실시간 잔여석·알림·네이티브 앱·지도 검색·거리순 추천은 첫 공개에서 제외한다. 예약은 공식 예약 안내 또는 공식 사이트로 연결한다. 광고 배치와 정책 검증은 P07·P15에서 다룬다.

웹뷰 앱은 웹 첫 공개 이후의 후속 목표다. 별도의 서비스 기능·화면을 중복 구현하기보다 검증된 모바일 웹 화면을 재사용한다. 대상 플랫폼·앱 구성 도구·앱 배포 일정은 미정이며 [PLAN의 P23](../PLAN.md#미완료후속)에서 별도로 준비한다.

## 첫 공개 흐름과 후속 범위

현재 첫 공개는 홈 발견 → 이름/지역/종류 검색 → 상세/공식 출처 확인 흐름이다. 비교·비교 담기·비교 URL·개수 제한은 제외한다. 북마크·로그인·상황별 AI 추천은 후속 보류이며 현재 시안의 미연결 표시를 기능 제공으로 취급하지 않는다.

홈에서 지역·종류 조건을 적용/취소/초기화하고 검색으로 전달할 수 있어야 한다. 검색은 별도 페이지이며 홈·검색·상세·정책의 이동에서 조건과 복귀 위치를 유지한다. UI 디자인 가이드는 공개 서비스 내비게이션에 연결하지 않는다. 메뉴·버튼 위치·색상·폭·팝업/푸터 형태와 검토 상태는 [DESIGN](../DESIGN.md)에서 관리한다.

날짜 운영·요금 정보가 대부분 미확인인 현재 자료로는 방문일/요금 필터의 효용이 낮아 첫 공개에서 분리하고 확인 데이터 확보 뒤 P32에서 도입 여부를 검토한다. 이름·지역·종류 검색과 확인된 행사 기간에 따른 진행 중/다가오는 구분은 유지하며, 기간 구분을 방문일 운영 필터로 해석하지 않는다. 날짜 입력·달력 P27 검토는 유지하되 제품 필터 활성화와 구분한다. 요금·할인·예약의 확보 정보와 미확인 표시는 상세에 유지한다.

구현·공개 운영·앱 준비·후속 검토의 현재 상태와 순서는 [PLAN](../PLAN.md)에서 관리한다.

이전 비교·날짜/요금 필터의 기준은 아래 후속 절에서 참고용으로 보존하며 현재 구현 완료 조건으로 해석하지 않는다.

## 홈과 페이지 구성 방향

홈에서 발견하고 별도 검색·상세로 이동한다. 다섯 종류의 검색 범위는 유지하며 섹션·카드·내비게이션의 구체적인 배치는 DESIGN의 검토 결과를 따른다.

- 홈의 지역 기본값은 전체 지역이다. 실제 확보한 지역·종류·항목만 노출하며 전국 데이터를 모두 확보했다고 안내하지 않는다.
- 진행 중·다가오는 구분은 Asia/Seoul 기준 날짜와 확인된 행사 시작/종료일을 따른다. 진행 중인 행사 기간이라는 표시를 당일 개장·휴무 없음·예약 가능·잔여석 보장으로 해석하게 하지 않는다. 취소·종료·날짜 누락의 처리는 기존 기준을 따르며 출처 안내는 공통 푸터의 서비스·데이터 출처에서 제공한다.
- 홈의 진행 중·다가오는·상설 구간과 정렬·노출 건수·더 보기 목적지는 [현재 채택 기준](../DESIGN.md#현재-적용한-화면-기준)을 따른다. 상설 시설과 기간/운영 미확인 항목을 진행 중 행사로 임의 분류하지 않으며, 미확인 항목은 일반 검색에서 확인한다. 정상 빈 섹션과 조회 실패를 구분한다.
- 홈·검색·상세·정책 사이에서 검색 조건과 필요한 복귀 위치를 유지한다. URL·뒤로 가기·새로고침의 상세 동작은 P13에서 실제 데이터와 검증한다.
- 홈·검색 카드에서 간단 보기 바텀시트를 열고, 그 안의 상세 정보 보기로 개별 `/detail/[id]` 페이지에 이동한다. 시트는 목록 문맥과 조건을 유지하며 닫기·뒤로 가기로 복귀하고 상세는 직접 접속도 지원한다. 카드의 사진 설명은 반복하지 않되 이미지 대체 텍스트·저작권 출처는 접근 가능하게 유지한다. 미확인 운영·요금은 간단 보기와 상세에서 명시한다. 시트 움직임과 화면 구성은 DESIGN의 현재 기준을 따른다.
- 개인정보처리방침·이용약관·서비스/데이터 출처 안내에 모바일과 PC에서 접근할 수 있게 한다. 운영자·저작권 표시와 정책 내용은 실제 운영 구성에 맞춰 P15에서 준비하며 미정 값이나 샘플 약관을 최종 정책으로 표시하지 않는다.
- 공통 바텀시트는 상단 핸들의 터치·마우스 드래그로 확장·축소·닫기를 지원한다. 내용 스크롤과 구분하고 X·키보드 닫기, 닫은 뒤 포커스·스크롤 복귀를 유지한다.
- 페이지 이동은 공통 사람 모양 로딩 한 개로 표시하며 링크 옆이나 화면 우측의 별도 문구를 반복하지 않는다. 버튼·화면 배치를 유지하고 스크린리더 상태 안내와 실제 오류·재시도를 제공한다.
- 새 페이지와 검색 조건·페이지 변경은 상단/본문 포커스에서 시작하고 뒤로·앞으로 가기는 이전 위치를 복원한다. 같은 페이지의 모달 닫기는 위치·열기 버튼으로 복귀하며 다른 페이지 이동과 구분한다. 갱신 확인 안내는 오래된 원천 확인·최근 재조회 실패를 뜻하며 현재 진행 중인 작업으로 표현하지 않는다. 일반 힌트와 확인 필요를 제목·아이콘으로 구분하고 방문에 필요한 안내는 본문에 계속 표시한다.

## 기능별 완료 판단 기준

### 검색·목록

- 검색 범위는 전체 / 행사 기간 진행 중 / 14일 안에 시작 / 상설 시설 중 하나를 선택한다. 홈에서 넘어온 구분을 미리 선택하고 같은 폼에서 변경한다. 검색 버튼으로 조건을 함께 적용하며 전체 선택은 범위만 해제하고 이름·지역·종류·정렬을 보존한다. 기존 7/30일 검토 URL은 실제 적용된 구간을 표시하고 유지할 수 있다.
- 키워드는 이름의 부분 일치로 찾는다. 시도·종류는 각각 하나씩 선택하며 모든 선택 조건을 함께 적용한다. 방문 날짜·요금 필터는 P32 후속 범위이며 첫 공개에서는 제공하지 않는다. 공백 키워드는 미입력으로 처리한다.
- 취소된 행사와 종료된 기간 행사는 일반 검색에서 제외한다. 저장된 상세 URL에서는 취소·종료 상태를 볼 수 있고 출처는 공통 푸터 안내에 접근할 수 있다. 상태 판정에 필요한 정보가 누락되면 상태 미확인으로 표시한다.
- 기본 검색은 진행 중·예정 기간 행사를 시작일 순으로, 이후 상설 시설을 이름 순으로, 일정·상태 미확인 항목은 마지막 이름 순으로 보여준다. 동일한 값은 안정된 식별자로 순서를 유지한다. 페이지당 20개를 제공한다.
- URL에 키워드·지역·종류·기간 구분·페이지를 보존한다. 새로고침·직접 접속·브라우저 뒤로 가기에서 조건을 복원하고, 조건 변경 시 첫 페이지로 이동한다.
- 검색 하단은 페이지 번호와 이전·다음 화살표로 이동하며 현재 번호를 표시한다. 첫/마지막의 비활성 화살표 자리와 검색 조건을 유지한다.
- 유효하지 않은 필터·페이지 값은 기본값으로 정리하고 적용된 조건과 URL이 일치해야 한다. 요청 실패를 결과 0건으로 표시하지 않는다. 후속 날짜 필터의 검증은 P32에서 다룬다.
- 목록에 이름·종류·지역·기간 또는 상설 구분·상태를 표시한다. 홈·검색 카드의 지역은 간단 보기·상세와 같은 확인된 시군구까지 표시하고 누락·주소 근거 충돌은 시도만 유지한다. 상세 주소는 이용 정보에서 제공한다. 일반 입장료 정보를 함께 제공할 경우 무료·유료·미확인을 구분하고, 누락을 무료로 바꾸지 않는다. 카드의 구체적인 배치는 P24·P26에서 검토한다. 로딩, 결과 없음, 조회 실패를 구분하고 조건 초기화·재시도를 제공한다.

### 상세

체험·추가 요금·할인·예약 안내는 확보한 문장이 있을 때 표시한다. 값 없는 선택 안내를 고정 미확인 행으로 반복하거나 할인/예약이 없다고 단정하지 않는다. 운영 시간·휴관·입장료·주소·연락처 같은 핵심 정보의 누락은 기존 미확인 표시를 유지한다.

- 이름·종류·지역·주소와 행사 기간 또는 시설 운영 정보를 제공한다. 운영 시간·휴관일·예약 기간은 서로 분리한다. 확인되지 않은 값은 항목별 미확인으로 표시한다.
- 일반 요금은 대상별 단가와 적용 기준을 표시한다. 특별전·체험·주차 등 확인된 추가 요금은 일반 요금과 분리한다. 할인은 대상·기간·증빙·중복 가능 여부를 표시하며 누락된 조건을 채워 넣지 않는다.
- 상세는 같은 원천·대상·필드의 최신 유효 기준일 근거를 우선하고 원문·선택 전 근거를 보존한다. 실패·빈 응답·누락은 이전 유효 값을 지우지 않으며 원래 출처·기준일·확인 시각을 유지한다. 동일 기준일 차이는 충돌로 남기고 교차 원천의 수집 시각을 최신 사실의 기준으로 사용하지 않는다. 그룹별 표준 우선은 표시 기준이며 현장 사실의 보장이 아니다. 같은 주소·연락처·링크는 한 번 표시하고 연락처 역할·평일/휴일 시각과 예외를 구분한다. 상세 주소는 도로명을 우선하고 지번·상단 성인 요약을 생략한다. 대상별 요금·주민 할인·무료 조건·기간을 보존하며 0원은 해당 대상의 무료, 누락은 미확인이다.
- `[이용요금]` 등 명확한 요금 블록은 조건·예외와 함께 입장료 또는 체험·추가 요금에 연결하고 프로그램/추가 안내에 중복 표시하지 않는다. 셔틀·주차·체험만 안내한 문장은 입장료로 분류하지 않는다. 불명확한 혼합 요금은 블록 전체를 보존하고 일반 입장료를 추정하지 않는다. 원천의 불완전 괄호는 내용을 만들어 복구하지 않는다.
- 할인 기간·증빙·중복 적용은 확보한 요금/할인 원문의 조건을 표시하고 자동 적용하지 않는다. 현재 원천에는 예약 기간·실시간 잔여석 전용 필드가 없으므로 별도 고정 미확인 행을 반복하지 않는다. 실제 예약/방문 조건은 본문에 유지하고 안내 누락·링크 유무로 예약 필요/가능 여부를 추정하지 않는다. 해당 필드를 확보하면 근거와 함께 각각 추가한다.
- 공통 데이터·사진 원천과 이용 조건은 푸터의 서비스·데이터 출처에 모으며 정보 항목마다 출처·시각을 반복하지 않는다. 상세 사진별 출처 접근은 아래 갤러리 기준을 따른다. 최근 자료 확인일은 상세 하단 공식 안내·예약 영역 아래, 푸터 위에 날짜와 의미를 짧게 한 번 표시한다. DB/API에서는 항목별 근거와 수집 시각·마지막 원천 확인 시각을 구분해 보존한다. 오래됨·최근 조회 실패는 해당 자료에서 갱신 확인 필요로 표시한다. 원천 확인은 원천 응답을 마지막으로 확인한 시각이며 현장 운영을 보증하지 않는다.
- 소개는 처음 5줄과 전체 펼침을 제공한다. 소개와 같은 행사소개는 중복 표시하지 않고 다른 행사소개는 소개에 보존한다. 행사내용은 고정된 주요 프로그램 제목 아래 항목 이름과 본문으로 표시하며, 긴 본문만 소개와 같은 5줄/더 보기·접기를 제공한다. 다른 항목과 중복되지 않는 내용이 있을 때만 추가 안내를 표시하며 항목 이름·값의 형식은 이용 정보와 통일한다. 화면의 중복 정리는 원천 데이터 변경과 구분한다. 상세 상단은 간단 보기와 같은 확인된 시도·시군구를 표시하며 시군구가 누락되거나 충돌하면 시도만 표시한다. 상세 주소는 이용 정보에서 제공한다.
- 실제 사진은 확인한 TourAPI 제1유형의 대표 사진을 목록·간단 보기·상세에 연결한다. 목록의 작은 썸네일은 원본 비율을 유지해 정사각형 영역을 채우며 일부 가장자리가 잘릴 수 있다. 간단 보기·상세에서는 전체 사진을 표시하고, 없거나 원천 이미지 로딩에 실패하면 종류 아이콘을 제공한다. 출처 안내에는 제공기관·원천 링크·이용 유형을 모으고 DB에는 사진별 URL·저장 응답 근거를 보존한다. 외부 URL 표시는 로컬 파일 확보를 의미하지 않으며 미확인/제3유형 사진이나 다른 장소의 표본 사진을 실제 자료에 대신 쓰지 않는다.
- 상세는 기존 대표를 먼저 표시하고 허용 사진이 여러 장일 때 수동 이전/다음·현재 번호·썸네일 선택·모바일 스와이프·키보드 이동을 제공한다. 자동 재생은 하지 않으며 한 장이면 넘김 제어를 생략한다. 사진 한 장의 실패가 다른 정상 사진을 숨기지 않는다. 사진별 출처와 대체 텍스트에 접근할 수 있어야 하며 목록·간단 보기는 기존 대표 한 장을 유지한다. 대표가 없던 대상은 동일 contentid의 검토한 첫 허용 사진을 사용한다. 빈 상세 사진 목록은 저장된 이용 가능 사진 없음이다. 계약은 [백엔드 README](../backend/README.md#상세-근거와-미확인-정보)를 따른다.
- 제공처·이용 조건이 같은 사진은 공통 출처와 이용 유형으로 간단히 안내하고 사진 이름을 모두 나열하지 않는다. 개별 작성자·원본·라이선스·변경 표시가 필요한 사진은 접힌 안내에서도 해당 조건을 지키며, DB의 사진별 출처와 이용 조건은 보존한다. 현재 사진의 판단 근거는 [이용 조건](DATA_SOURCES.md#이용-조건)에 둔다.
- 변경·취소·종료·수집 실패를 구분한다. 갱신 실패 시 마지막으로 확보한 정보를 유지하고 상세에 갱신 확인 필요를 표시한다. 실패·마지막 성공 시각은 DB/API 근거에 보존한다. 실패만으로 행사 취소를 추정하지 않는다.
- 존재하지 않는 식별자는 찾을 수 없음으로 응답한다. 일시적인 조회 실패는 오류와 재시도를 제공하며 찾을 수 없음으로 처리하지 않는다.
- 공식 안내 링크와 원천에서 확보한 실제 예약 링크를 제공한다. 예약 링크가 없으면 누락 안내는 생략하고 섹션 제목은 공식 안내로 표시한다. 링크 유무로 예약 필요 여부를 추정하거나 직접 예약 기능·예약 가능 여부를 만들어 표시하지 않는다.

### 방문 날짜·요금 필터 — 첫 공개 제외·후속 검토

P32에서 확인 데이터 확보·효용을 검토한 뒤 재개 여부를 정할 참고 기준이다. 첫 공개에는 활성 필터로 포함하지 않으며, 아래 기준만으로 후속 도입을 확정하지 않는다.

- 요금 필터는 할인 없는 일반 성인 입장 기준으로 무료·유료·미확인을 구분한다. 무료 입장에 유료 체험이 있는 경우 목록에도 별도 요금 존재를 표시한다. 일반 요금의 기준이 불명확하면 미확인으로 분류한다.
- 방문 날짜는 Asia/Seoul의 오늘 이후 달력 날짜이며 오늘을 포함한다. 과거 날짜는 유효하지 않은 조건으로 처리한다. 기간 행사는 시작일과 종료일을 포함하고 확인된 휴무·취소를 반영해 일치 여부를 판단한다. 상설 시설은 확인된 운영 요일·휴관일·임시 휴관을 적용한다. 상설 시설도 날짜·운영 조건을 확인하지 못하면 방문 가능으로 추정하지 않는다.
- 날짜를 선택했을 때 그날 운영이 확인된 후보만 결과에 포함한다. 운영 여부를 판단할 수 없어 제외된 후보가 있다면 그 사실을 안내한다. 날짜 조건을 해제하면 해당 후보를 일정 미확인 표시와 함께 찾을 수 있다.

### 비교 — 현재 제외·과거 기준 보존

2026-10-02의 최초 기준이다. 2026-10-04 현재 화면·첫 공개에서 제외했으며 재개 시 필요성과 범위를 다시 검토한다.

- 목록·상세에서 최대 3개를 선택한다. 같은 후보의 중복 선택을 막고, 네 번째 후보를 선택하면 기존 후보 제거가 필요함을 안내한다. 2개 이상일 때 비교를 실행할 수 있다.
- 비교 후보 식별자와 방문 날짜를 URL에 보존해 새로고침·직접 접속으로 복원한다. 날짜의 유효성은 검색과 같은 기준으로 처리한다. 검색 화면의 현재 페이지는 비교 후보를 제한하지 않는다.
- 이름·지역·종류·기간 또는 운영 조건·선택 날짜의 운영 여부·일반 요금·추가 요금·할인·예약 조건·출처·확인 시각을 동일한 항목으로 표시한다.
- 날짜 미선택 시 운영 여부는 날짜 미선택으로 표시한다. 선택한 날짜의 운영 여부는 가능·불가·미확인을 구분하며 예약 가능이나 잔여석 확보로 표현하지 않는다.
- 할인 자격을 자동 적용하지 않고 대상별 공지 요금을 나란히 보여준다. 미확인 항목을 0원이나 할인 없음으로 치환하지 않으며 최저가 순위·개인별 합계를 제공하지 않는다.
- 후보를 제거하고 상세로 이동할 수 있다. URL의 중복 식별자는 하나로 정리하고 3개 초과 시 앞의 3개만 유지해 안내한다. 삭제·존재하지 않는 후보는 안내 후 제외하고, 2개 미만이면 재선택 안내를 제공한다. 일시적인 조회 실패는 후보를 지우지 않고 오류·재시도를 제공한다.

### 검색 유입과 공개 확인

- P13에서 실제 자료를 화면에 연결할 때 홈·검색·상세의 핵심 정보를 본문 HTML로 제공하고, 페이지의 주제와 소제목 순서를 읽기 쉽게 구성한다. 목록에서 공개 상세로 이동하는 경로는 검색엔진이 따라갈 수 있는 링크로 제공한다. 팝업 동작과 직접 접속 가능한 상세 주소를 함께 유지한다.
- P14에서 제목·설명·본문·주소·검색 노출 설정을 페이지별로 대조하고 어색한 표현·중복·불일치를 필요한 범위에서 수정한다. 상세·확보된 지역·종류 페이지는 실제 장소명·지역·종류·내용과 맞는 고유 제목·설명을 제공한다. 검색어 반복·확인되지 않은 운영/요금·없는 지역 소개나 행사 정보를 만들지 않는다.
- 홈·상세·지역·종류와 검색어/조합 필터·페이지 구분·빈 결과·오류·종료/취소 상세·정책·디자인 가이드의 색인 대상을 구분하고 판단 근거를 기록한다. 현재의 개발·검토용 검색 제외 설정을 공개 대상별 정책으로 정리하며 개발/검토 화면은 계속 구분한다. 구체적인 URL과 색인 선택은 P14에서 실제 화면·자료를 확인해 정한다.
- 같은 내용을 가리키는 주소의 대표 주소(canonical), 내부 링크·리다이렉트·sitemap이 서로 맞는지 확인한다. sitemap에는 선택한 공개 색인 대상의 유효한 대표 주소만 넣고 없는 상세는 404로, 조회 실패는 정상 상세와 구분해 응답한다. 검색 제외(noindex)와 수집 접근 제어(robots.txt)의 목적을 구분하고 서로 필요한 검사를 막지 않게 구성한다.
- P14 완료는 대표 페이지의 응답 HTML·제목/설명·제목 구조·상세 링크·상태 코드·대표 주소·검색 노출 설정·sitemap을 확인하고 필요한 수정·검증·자체 리뷰를 마친 상태다. 실제 도메인에 의존하는 주소는 공개 설정과 연결해 검증하고 로컬 주소를 공개용 값으로 남기지 않는다. 실제 공개 후 수집/색인 상태 확인은 P15에서 수행하며 기술 설정 완료와 검색 노출·순위 결과를 구분한다. 기술 확인 시 [Google 검색 개발자 안내](https://developers.google.com/search/docs/fundamentals/get-started-developers)를 참고한다.
