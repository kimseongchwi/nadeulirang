# 제품 요구사항 (PRD)

상태: 첫 공개 범위 검토 중 · 갱신일: 2026-10-01

PRD는 Product Requirements Document, 제품 요구사항 문서다. 무엇을 만들고 어떤 동작을 충족해야 하는지 정의한다. 작업 순서·진행 체크는 [PLAN의 P05](../PLAN.md#요구사항과-디자인)에서 관리하며, 아래 세부 범위는 확정 전 제안이다.

## 서비스 목표

전국 축제·행사·전시·박물관·문화관광지의 일정·요금·할인 조건을 검색·비교한다. 개인 프로젝트로 운영하며 검색 유입과 광고 수익을 목표로 한다. 여러 공식 사이트에서 방문 조건을 반복 확인하는 불편을 줄인다.

## 첫 공개 범위 제안

| 기능 | 기대 동작 |
|---|---|
| 검색·목록 | 키워드·지역·종류·방문 날짜·요금 여부로 후보를 찾고 조건을 URL로 유지 |
| 상세 | 일정·운영·일반 요금·추가 요금·할인·예약 조건과 공식 링크 제공 |
| 비교 | 동일한 방문 기준으로 후보의 일정·요금·할인 조건과 미확인 항목을 비교 |
| 검색 유입 | 상세·유효한 지역·종류 페이지에 본문 HTML과 고유 메타데이터 제공 |

로그인·결제·직접 예약·리뷰·실시간 잔여석·알림·네이티브 앱은 초기 범위에서 제외하는 방향을 제안한다. 비교 개수, 할인 입력과 예상 합계 제공 범위는 검토 후 결정한다.

## 정보·계산 기준

- 무료·유료·미확인을 구분하며 누락된 요금을 무료로 바꾸지 않는다.
- 일반 관람료와 특별전·체험 요금을 분리하고 할인 대상·기간·증빙·중복 여부를 표시한다.
- 조건이 모두 확인된 경우에만 예상 합계를 제공한다. 조건부 최저 요금을 모든 방문자의 실제 결제 금액으로 표시하지 않는다.
- 상설 시설과 기간 행사를 구분하고 날짜·운영 시간·예약 기간을 분리한다. 기준 시간대는 Asia/Seoul이다.
- 출처 URL·원본 식별자·수집 및 확인 시각을 보존하고 저장된 데이터를 조회한다. 수집 실패·변경·취소 상태를 구분한다.
- 실제 확보한 지역·시설·정보의 범위를 표시한다. 모든 시설과 모든 할인 정보를 확보했다고 표현하지 않는다.

## 구현 전 검토할 항목

첫 원천과 시설 표본, 필수 정보와 누락 허용 범위, MVP 포함 기능, 비교·할인 입력 방식을 검토한다. 데이터 원천의 필드·갱신 주기·호출 제한·상업적 이용·이미지 조건은 P06에서 확인한다.

색상·폰트·화면 형태는 [DESIGN](../DESIGN.md), 작업 순서와 완료 기준은 [PLAN](../PLAN.md)에서 관리한다.
